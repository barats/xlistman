# Subscriber-as-email-address identity model

xListman uses email addresses as the primary identity, with no User/account concept. Each email address is an independent entity; a person with multiple addresses manages each independently. This is the Mailman 2 model, chosen over the Mailman 3 User-with-multiple-addresses model for simplicity. The trade-off is the loss of multi-address convenience (a person cannot see subscriptions across all their addresses in one login). We accepted this cost because the subscriber-focused model eliminates account management (no passwords, no password resets, no account linking) and pairs naturally with magic-link authentication. Web UI authentication uses one-time magic links sent to the subscriber's email address, with a persistent session cookie. Roles (Owner, Moderator) are tied to email addresses, not users.
