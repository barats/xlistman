# MTA integration: LMTP + pipe inbound, SMTP outbound

xListman receives inbound mail via two paths: a long-lived LMTP server (the primary, efficient path used by Postfix/Exim) and a pipe mode (fallback for simpler MTAs, where the MTA pipes messages to the binary as a subprocess). The pipe mode relays to the running daemon via a local Unix socket rather than processing independently, keeping a single writer to the database. Outbound mail is sent via SMTP to the MTA's submission port. We chose LMTP as the primary inbound path because it is purpose-built for final delivery to a mail processing agent, avoids per-message process startup, and has first-class support in Postfix and Exim. Pipe mode is supported for compatibility with constrained hosting environments. The relay-to-daemon design for pipe mode avoids SQLite write-contention and keeps processing logic in one code path.
