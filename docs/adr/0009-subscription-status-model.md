# Subscription Status model

Subscriptions carry an explicit four-state Status (Pending, Active, Held, Disabled) instead of a `ConfirmedAt` timestamp or a `Disabled` boolean. A subscription is created Pending when someone requests to join, moves to Active on email confirmation (or to Held on confirmation for Moderated lists), and to Disabled when the bounce threshold is exceeded. Only Active subscriptions receive posts. We chose an explicit Status over the alternatives — deriving "pending" from a null `ConfirmedAt` timestamp, or treating the confirmation token as the pending marker with no Subscription row until confirm — because a timestamp-as-state is fuzzy to reason about and a token-as-marker leaves no home for the Held state that Moderated lists need. The single Status column gives all three states a clear home and keeps delivery logic a simple "Status == Active" check. Manual owner actions (CLI `subscriber add`/`import`) create Active subscriptions directly, bypassing opt-in; a duplicate Pending request re-sends the confirmation email instead of erroring.
