# Web admin console: settings, membership, and roles

Phase 6 extends the Phase 5 web role console (ADR 0015) into a per-list admin console: an Owner configures list settings, manages members, and grants or revokes the Owner and Moderator List Roles from the web, while the CLI gains parity commands (`moderator`, `subscriber approve/reject`, `list config`) so the two admin surfaces share the same store functions and cannot drift. Ownership boundaries: an Owner controls only their own lists; deleting a list and changing its ListType remain server-admin CLI operations (ADR 0005); and Moderators keep moderation only — no settings, no member list, matching Mailman. Adding a member is authoritative, mirroring the CLI: the Owner's action stands in place of double opt-in and creates an Active subscription immediately, including for addresses not previously known as Subscribers, because there is no stored verification flag to preserve and the Owner is the trusted actor. Held Subscriptions (the Moderated policy) gain their previously missing resolution path — approve or reject from the Members tab — fixing a dead end where a confirmed subscription request could sit in Held forever with no way to act on it. Role changes respect a last-owner guard: a list can never have zero Owners. Notification settings that existed but were unwired now fire: welcome on approval (WelcomeEmail), goodbye on Owner removal (GoodbyeEmail), a pending-approval notice at confirm time, and a rejection notice when a request is declined.

**Considered Options**:
- Invite/confirm flow for Owner-added members instead of authoritative add — rejected: it would diverge from the CLI's GetOrCreateSubscriber behavior, contradict every existing admin path, and add friction to a deliberate Owner action with no stored verification concept to defend.
- Granting Moderators a read-only member list and settings — rejected: member addresses stay private to Owners, and the Moderator role is scoped to moderation.
- Web-only Phase 6 with no CLI parity — rejected: the CLI could not assign the Moderator role (unassignable in any shipped path) nor resolve Held Subscriptions; leaving those gaps in the server-admin tool would be a regression.
- Owner-initiated list deletion and type changes from the web — rejected: destructive and structural operations stay with the server administrator (ADR 0005), keeping the web console for day-to-day management.
