# SPA mode for SvelteKit frontend

The SvelteKit 5 frontend is compiled to static files using `@sveltejs/adapter-static` and embedded into the Go binary via `go:embed`. This means SvelteKit runs in SPA/SSG mode, not SSR (Server-Side Rendering). The Go binary serves static files and a JSON API; SvelteKit handles client-side routing and rendering with data fetched from the API. We chose this over SSR mode (which would require a Node.js runtime alongside Go) because it preserves the one-binary, no-external-runtime-dependencies promise that is xListman's core value proposition. The trade-off is the loss of SvelteKit's server-side rendering, form actions, and `+page.server.ts` load functions. This is acceptable because the public pages (list index, list info) are simple enough that client-side rendering with SSG shells is sufficient, and the authenticated pages are behind magic-link auth where SEO and first-paint performance are not critical. The frontend stack is TypeScript + SvelteKit 5 + shadcn-svelte, which all work in SPA mode.
