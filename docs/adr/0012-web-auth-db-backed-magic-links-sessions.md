# Web auth: DB-backed magic links and sessions

Web authentication uses one-time Magic Links and server-side Sessions stored in the database, extending the passwordless decision in ADR 0003. We considered stateless HMAC-signed tokens (a signed cookie carrying email + expiry, no server-side state) as an alternative, but the codebase already contained a fully implemented and tested DB-backed layer — the `magic_links` and `sessions` tables, their store methods, and migrations — so DB-backed wins on cost while adding real value: individual revocation (logout, kill a session), an audit trail of logins, and no secret-key management for signing. Its two costs, a DB write per login and stale-row growth, are small; the Phase 2 expiry sweeper that already clears expired held messages is extended to prune expired Magic Links and Sessions. Stateless was rejected mainly because its headline advantage — no new tables and no cleanup — was already moot given the existing schema, and it forfeited revocation.
