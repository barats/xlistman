# Digest worker: elapsed-based self-healing scheduling

Digest-mode subscribers receive a per-list compilation of posts on a daily or weekly cadence, built as a MIME `multipart/digest`. The digest worker compiles from the archive — the single source of truth — using a per-list watermark `last_digest_sent_at`: when `now - watermark` reaches the list's frequency (24h daily, 7d weekly), every archived post since the watermark is compiled into a `multipart/digest` (a table-of-contents preamble plus each message as a `message/rfc822` part) and sent to Active digest-mode subscribers through the outbound queue with per-subscriber VERP envelope senders. The watermark advances on every run, send or skip, so an empty window closes empty and nothing accumulates silently; a run with no new messages sends nothing.

We chose elapsed-based anchoring over wall-clock fixed send times (e.g., "daily at 09:00") because it is self-healing: if the daemon is down past a due point, the next run sees an old watermark and sends the accumulated digest with no catch-up logic, and it needs no per-list time configuration. The wall-clock alternative is friendlier to a reader's expectation but adds a configuration surface, handles missed runs awkwardly, and still cannot satisfy every subscriber's local time. The watermark update is an atomic compare-and-swap (`UPDATE ... WHERE last_digest_sent_at < now`) so multiple instances cannot double-send (ADR 0008).
