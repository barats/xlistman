# Archive full-text search with SQLite FTS5

Archive browsing in the web UI includes full-text search over post subject and body, implemented with SQLite FTS5 virtual tables maintained from the `archive` table, rather than an external search engine or a `LIKE` scan. We verified FTS5 works through the pure-Go SQLite driver (glebarez/sqlite) in use, so this adds no new dependency and preserves the one-binary promise. FTS5 gives real tokenized full-text matching with ranking (and optional prefix queries) that `LIKE '%term%'` cannot, while staying inside the existing database so there is no separate index to sync or deploy. The trade-off is index maintenance: every archived message must also be written to the FTS table, and schema/reindex concerns live in the migration layer.
