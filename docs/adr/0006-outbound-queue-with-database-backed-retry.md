# Outbound queue with database-backed retry

All outbound mail (posts, digests, notifications, confirmation emails) flows through a persistent queue stored in the database. A background worker sends messages via SMTP to the MTA with exponential backoff on failure (1m, 5m, 15m, 1h, up to 24h). After max retries, the message is bounced to the original sender. We chose this over fail-fast (returning 4xx on the LMTP connection to let the MTA retry) because the LMTP path is only one of several outbound triggers - digests, notifications, and pipe-sourced messages have no MTA retry to fall back on. A uniform queue handles all outbound mail consistently, provides visibility via Prometheus metrics (queue depth), and ensures no messages are lost during MTA downtime. The queue is stored in SQLite (or the configured backend), so it survives daemon restarts.
