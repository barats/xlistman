# Moderation via email and CLI

Held messages are acted on by Owners and Moderators through two paths. The email path: the hold notification's Reply-To is a `listname-moderate+token@domain` address, and the first word of the reply body selects a Moderation Action (Approve, Reject, or Discard); the actor's sender address is verified as an Owner or Moderator of the list, and the token is an opaque per-message value, not the raw held-message ID. The CLI path: `xlistman moderation list/approve/reject/discard` for server administrators and automation. Approve delivers the held post to the list (archive + enqueue, skipping the posting policy); Reject discards it and notifies the sender; Discard removes it silently. Hold notifications go to all Owners and Moderators (deduplicated) with the full held message, and to the sender when `sender_held_notice` is enabled. Expired held messages are silently discarded by a periodic sweeper. We chose email + CLI over web URLs because the web UI is deferred (ADR 0007), and over CLI-only because moderators are not server administrators (ADR 0005 covers only server administration).
