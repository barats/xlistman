# Operational: the audit UI surface (per-list and server, with filter)

Verifies the Audit tabs themselves render events and that the action filter
narrows them — both the per-list view (Owner) and the instance-wide view
(Administrator). The events are generated by the operational tests themselves
(t09: subscription approve/reject on mod@; t10: moderation reject/discard on
mod@; t14: list create/type/delete and admin designate/revoke).

## Steps

1. `login as owner@lists.test`
2. `navigate to /admin/l/mod@lists.test/audit`
3. `expect text "Audit trail" to appear`
4. `expect text "Approved a subscription" to appear`
5. `expect text "Rejected a held message" to appear`
6. `expect text "Discarded a held message" to appear`
7. `select "Filter by action" to moderation.reject`
8. `expect text "Rejected a held message" to appear`
9. `expect text "Discarded a held message" to be absent`
10. `select "Filter by action" to ""`
11. `expect text "Discarded a held message" to appear`
12. `ensure anonymous`
13. `login as admin@lists.test`
14. `navigate to /server/audit`
15. `expect text "Audit trail" to appear`
16. `expect text "Created a list" to appear`
17. `expect text "Designated an administrator" to appear`
18. `select "Filter by action" to list.type`
19. `expect text "Changed a list type" to appear`
20. `expect text "Created a list" to be absent`
21. `expect 0 console errors`
22. `expect no API request to return a 5xx`
